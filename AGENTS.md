# J Road website collaboration

- Use the `sen` branch for this workspace's website changes. Check the active branch before editing, committing, or pushing. Push website proposals only to `sen`.
- Test the proposed changes and report what changed, what you verified, and the branch or preview link. Open or update a pull request to `main` only when asked for a review handoff.
- Leave merges into `main` and production deployments to the repository maintainer. When presenting a website proposal, do not ask the contributor whether to merge, offer to merge, or merge the proposal yourself.
- Use development data and settings for local or preview testing. Avoid production credentials and writes to production data for design proposals.
